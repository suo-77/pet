# 02 数据库完整表结构设计（MySQL）

> 字符集 utf8mb4 / 排序规则 utf8mb4_general_ci / InnoDB。
> 统一字段：`create_time`、`update_time` 使用 `DATETIME DEFAULT CURRENT_TIMESTAMP`（更新时间加 `ON UPDATE CURRENT_TIMESTAMP`）。
> 逻辑删除统一字段 `deleted TINYINT DEFAULT 0`。外键按业务对象建立（FileId 使用 MyBatis 结果映射，前端展示由后端拼接 URL）。

## 1. user 用户表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AI | 用户ID |
| username | VARCHAR(50) UNIQUE | 账号/登录名 |

| phone | VARCHAR(20) | 手机号(可空，验证码注册时必填) UNIQUE |
| nickname | VARCHAR(50) | 昵称 |

| status | TINYINT | 0正常 1禁用 |
| create_time / update_time / deleted | | |

索引：UK(username)、UK(phone)、IDX(nickname 前缀查询搜索)

## 补充说明
- 命名全部小写下划线，User -> `user`，CommunityPost -> `community_post`。
- 搜索场景（店铺名/宠物名/昵称）本期用 `LIKE '%kw%'` 前缀+全模糊，数据量小；预留后续接入全文/ES 的扩展点。
- 点赞权威数据：Redis 计数器（`post_like_count:{postId}`）为唯一计数源，MQ 消费者定时/批量同步该值到 `community_post.like_count`，并写 `post_like` 关系，幂等 Upsert。
